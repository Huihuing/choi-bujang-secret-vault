# 워치독스 · BYTE BACK Vercel 통합

## 화면과 데이터 경로

운영 주소는 `https://choi-bujang-secret-vault-jwnp.vercel.app/`다. 기본 화면은 워치독스이며 상단 BYTE BACK 메뉴로 기존 자료실을 연다. 두 화면을 오가도 자료실 페이지를 다시 로드하지 않아 기존 메모리 로그인 세션을 유지한다. 메뉴 전환은 인증이나 기기 승인을 대신하지 않는다.

워치독스 정적 화면은 학생 `on-client/student/pc-monitor/`의 HTML·JS·CSS 세 파일에서 빌드한다. 제공 `on-client/public/app.js`, 제공 서버, Windows 수집기, 자료실의 인증·기기 승인·서명 API를 복사하거나 변경하지 않는다.

측정 데이터는 이 화면을 사용하는 PC의 `http://127.0.0.1:5191`에서 브라우저로 직접 읽는다. Vercel의 API·Supabase DB·외부 중계로 전달하지 않는다. 조회는 수동 GET만 사용하며 자격 정보·로그인 토큰·쿠키를 보내지 않고 리디렉션도 따라가지 않는다. 조회 이력은 해당 탭 메모리에만 남는다.

## 실행과 확인

1. Windows PC의 기존 프로젝트 폴더에서 다음 명령을 실행한다. 이전 측정 서버가 켜져 있다면 원래 실행 창에서 Ctrl+C로 종료한 후 최신 소스로 다시 시작한다. 서버 코드 변경은 실행 중인 Node 프로세스에 자동 반영되지 않는다.

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\on-client\student\start-watchdogs.ps1
   ```

2. 운영 주소를 열고 워치독스의 「다시 조회」를 누른다. 첫 화면을 여는 것만으로 Windows 값을 수집하지 않는다.
3. 브라우저가 루프백·로컬 네트워크 접근 권한을 요청하면 본인이 직접 확인하고 허용한다. 거부했거나 측정기가 꺼졌다면 확인 불가와 다음 행동을 표시한다. 보호 설정·실험용 플래그·방화벽을 끄도록 안내하지 않는다.
4. CPU·메모리·디스크의 값·단위·출처·측정 시각과 조회 기록을 확인한다. 네트워크·방화벽·Windows 이벤트를 조회하고 종류 필터를 전환한다. Windows 경고·오류는 침해 판정이 아니다.
5. BYTE BACK 메뉴에서 기존 로그인·기기 등록·관리자 승인 흐름을 사용한다. 미승인 기기의 보호 자료 요청은 계속 거부되어야 한다. 실제 SDP/XDR 원천 연결은 별개다.

브라우저 또는 기기 정책 때문에 웹에서 로컬 조회를 할 수 없다면 `http://127.0.0.1:5191/`의 기존 화면을 사용할 수 있다. 다른 PC·휴대전화에서 운영 사이트를 열어도 이 PC의 값이 원격으로 전송되지는 않는다.

## 로컬 연결 경계

- 서버는 계속 `127.0.0.1`에 바인딩하고 정확한 로컬 Host만 받는다.
- 웹에서 읽을 수 있는 경로는 `/api/pc`, `/api/network`, `/api/sdp` 세 GET뿐이다.
- 허용하는 웹 Origin은 위 운영 주소 하나다. 다른 Vercel 하위 도메인·프리뷰·외부 사이트·와일드카드는 허용하지 않는다.
- 웹 요청에 Authorization·Cookie를 사용하지 않는다. 쿼리 포함 주소·정적 파일 접근·쓰기 요청·잘못된 Host는 측정 전에 거부한다.
- 서비스 워커는 정적 화면만 저장한다. 로컬 측정 응답·자료실 API·보호 메모는 캐시하지 않는다.

## 검증 기록

코드·모의 검사와 운영 HTTP·브라우저 검증은 각각 실행한 결과만 기록한다. 브라우저의 실제 권한 허용과 PC 조회를 확인하기 전에는 웹 실측 성공으로 보고하지 않는다.

현재 구현 검사: 측정 UI 모의 27개, 로컬 서버의 기존·웹 출처 경계 모의 28개, 자료실 인증·공개 집계·정적 빌드·메뉴 모의 44개가 통과했다. 합계 99개이며 실제 브라우저 권한과 운영 실측의 성공을 대신하지 않는다.

브라우저 권한의 근거는 [Chrome 로컬 네트워크 접근 안내](https://developer.chrome.com/blog/local-network-access)와 [Chrome 145 루프백·로컬 네트워크 권한 분리](https://developer.chrome.com/release-notes/145#local_network_access_split_permissions)를 따른다. 사용하는 브라우저·정책에 따라 허용 요청과 지원 범위가 다를 수 있다.
