# 워치독스 · 마지막 총공세 2~7일차 작업·인수인계 기록

> **최신 기준 · 2026-10-27:** 기록 타임라인형을 선택하고 프로젝트 폴더에서 워치독스를 실행한다. 6일차 제출 자료는 **GitHub 저장소 주소와 같은 작업의 40자리 커밋 SHA**이며, 7일차는 **핵심 기능 3가지의 실제 시연·근거·한계**를 정리한다. 포장·설치 프로그램·`package-app`·업데이트 실행은 이번 과정의 범위에서 제외한다.

## 기능의 출처와 이번 개선

조회 기록은 이 화면에서 수행한 PC·네트워크·Windows 기록·SDP 조회의 결과이며 조회 완료순으로 정렬한다. 실제 XDR 사건 발생순과 출처가 다르며, 브라우저 탭을 닫으면 사라진다. 기존 최근 PC 측정 최대 5회 비교와 CPU 변화량 `%p` 표시는 별도로 유지한다.

## 2일차 · CPU / 메모리 / 디스크

`pc-monitor/collect.ps1`이 `Win32_Processor.LoadPercentage`, `Win32_OperatingSystem`, `Win32_LogicalDisk.FreeSpace`를 읽는다. CPU 사용률은 %, 메모리 사용량과 디스크 여유는 GiB로 표시하고, 항목별 측정 시각·출처·확인 불가 사유를 남긴다. CPU는 WMI 스냅샷이므로 작업 관리자와 집계 시각·범위가 다를 수 있다.

**직접 확인:** 2026-10-27 16:48~16:49 KST, Node v24.19.0·일반 사용자 권한(관리자 권한 false)의 로컬 브라우저에서 CPU·메모리·디스크 세 값의 조회 성공을 확인했다. 새 UI에서도 다음 실측과 접속 실패 후 복구를 관측했다. 아래 시각은 브라우저 관측 시각이며 각 카드의 원천 측정 시각과 구분한다.

| 관측 시각 · KST | CPU | 메모리 사용량 | 디스크 여유 | 관측 |
|---|---|---|---|---|
| 2026-10-27 16:55 | 71 % | 15.4 GiB | 201.07 GiB | 새 UI에서 세 항목 조회 성공 |
| 2026-10-27 17:00:08 | 68 % | 12.38 GiB | 201.07 GiB | 학생 런처로 서비스 복구 뒤 Enter 재조회 성공 |

작업 관리자와 가까운 시각의 비교와 제3자 재현은 아직 미확인이다.

## 3일차 · 네트워크 / 방화벽 / Windows 이벤트

`Get-NetAdapter -Physical`로 연결된 물리 어댑터 수를, `Get-NetFirewallProfile`로 Domain/Private/Public 설정을, `Get-WinEvent`로 최근 24시간 System/Application의 Level 2 오류·Level 3 경고 건수를 읽는다. 로그별 1000건을 넘으면 부분 결과로 표시한다. 방화벽·로그·보안 정책을 변경하지 않는다.

**직접 확인:** 같은 2026-10-27 로컬 브라우저와 16:55 새 UI에서 물리 네트워크·방화벽 프로필·System/Application 조회 성공과 SDP 미연결 표시를 확인했다. 어댑터 수는 인터넷 접속이나 안전성의 증명이 아니며, Windows 경고·오류는 공격·침해 판정이 아니다. 실제 SDP/XDR 원천 연결은 미확인이다. 로그 권한 부족과 1000건 초과 부분 표본은 모의 검사에서만 확인했으며 실제 발생했다고 기록하지 않는다.

## 4일차 · 기록·다시 조회·오류·키보드

각 「다시 조회」가 수동 요청을 시작한다. 조회 전·조회 중·정상·부분 성공·실패를 구분하며, 재조회 중과 실패 때 이전 수치를 현재 값으로 표시하지 않는다. 실패에는 이유와 다음 행동을 붙인다. 버튼·선택 항목·텍스트 상태와 키보드 포커스를 제공한다.

이번 조회 기록 타임라인·종류 필터·20개 상한을 포함한 **UI 모의 검사 24개와 서버 모의 검사 9개, 총 33개가 통과**했다. 모의 검사와 아래의 실제 브라우저 관측, 공식 심판 판정을 구분한다.

| 실제 브라우저 관측 · 2026-10-27 KST | 확인한 결과 |
|---|---|
| 16:55 · PC와 네트워크 조회 | 타임라인 4개 기록 생성. 네트워크 버튼 한 번은 네트워크·Windows 기록·SDP의 3개 기록을 남긴다. Windows 종류 필터에서 전체 4개 중 1개 표시를 확인했다. |
| 16:56:56 · 에이전트가 직접 시작한 5191만 중단 | 실제 접속 실패, 현재 수치 삭제, 실패 사유·다음 행동, 실패 타임라인과 과거 성공 기록의 분리를 확인했다. WMI 권한 부족을 발생시킨 검사는 아니다. |
| 17:00:08 · 서비스 복구 뒤 Enter 재조회 | PC 세 값이 복구되고 과거 실패 기록이 유지되는 것을 확인했다. |

20개 상한·권한 부족·부분 표본은 모의 검사 근거만 있다. 실제 시연에서 해당 조건이 발생하거나 20개를 채웠다고 주장하지 않는다. 기존 2026-10-26 키보드·접속 오류 후 복구 근거도 보존한다.

5191은 5189와 별도인 학생용 동반 화면이다. 제공 보안 Agent의 서버 안에 Windows 계측을 통합했다고 설명하지 않는다.

## 5일차 · 프로젝트 폴더 실행과 타인 재현

Windows PowerShell 5.1과 Node v24.19.0 세션에서 저장소 루트를 연 뒤, 학생용 통합 시작 명령을 사용한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\on-client\student\start-watchdogs.ps1
```

상세 준비·이미 실행 중인 화면 처리·종료 방법은 [실행 안내](../student/pc-monitor/INSTALL.md)를 따른다. 기존 5189/5191이 켜져 있으면 중복 시작하지 않는다. 실행 화면의 **내 PC 상태·조회 기록·네트워크/Windows 기록**으로 이동하고 「다시 조회」를 누른다.

정상 결과는 실제 값·단위·출처·측정 시각이다. 읽기 실패는 이유·다음 행동을 표시한다. 실제 로컬 HTTP 검사에서 POST 405, 다른 Origin 403, 잘못된 Host 403을 확인했다.

**통합 시작 명령 검증:** PowerShell 5.1 파서 오류 0과 UTF-8 BOM을 확인했다. 두 앱이 이미 실행 중이면 재사용하고 종료 코드 0으로 끝났다. 17:00:08에는 기존 5189를 재사용하고 5191만 새로 시작한 뒤 PC 재조회가 복구됐다. Ctrl+C에서 이번에 시작한 5191만 종료하고 재사용한 5189의 HTTP 200을 보존하는 것을 확인했다. 이후 에이전트가 자신의 기존 5189도 정상 종료한 뒤 같은 한 명령으로 두 앱을 모두 새로 시작했다. 검증 종료 시 두 앱은 실행 중이었다. 다른 사용자가 안내만 보고 재현한 결과는 아직 미확인이다.

## 6일차 · GitHub 저장소와 40자리 커밋 SHA

제출 대상은 [기존 GitHub 저장소](https://github.com/Huihuing/choi-bujang-secret-vault)와 **이번 워치독스 작업이 포함된 동일 커밋의 40자리 SHA**다. 저장소 루트에서 다음 명령으로 현재 로컬 커밋을 확인할 수 있다.

```powershell
git rev-parse HEAD
git ls-remote origin refs/heads/main
```

미커밋 변경은 이 SHA에 포함되지 않는다. 최종 작업을 커밋·푸시한 뒤 두 명령이 반환하는 40자리 SHA와 GitHub의 main 커밋이 같은지 대조하고 제출 기록을 남긴다. 나중 작업의 커밋과 혼동하지 않도록 실제 제출할 때 이 두 값을 확인한다. 실제 제출·접수·수락은 미확인이다. 포장 파일이나 설치 프로그램의 생성 여부는 이번 6일차 조건으로 세지 않는다.

## 7일차 · 핵심 3기능 시연과 한계

1. **기록 타임라인:** 수동 조회 뒤 생성된 4개 기록과 Windows 종류 필터의 1개 표시, 접속 실패 기록과 복구 후 과거 기록 보존을 실제 시연했다. 조회 완료 시각과 원천 측정 시각, 기존 5189의 SDP/XDR 기록 출처를 구분한다. 최대 20개 상한은 모의 검사로 확인했다.
2. **내 PC 상태:** CPU·메모리·디스크를 다시 조회하여 실제 값·단위·출처·측정 시각 또는 확인 불가를 보여 준다.
3. **주의·연결 및 Windows 기록:** 물리 네트워크·방화벽·System/Application 조회·필터와 별도 SDP 미연결 표시를 실제 확인했다. 권한 부족·1000건 초과 부분 표본은 모의 검사 근거로 구분한다.

시연 화면에서는 계정·확인 번호·키·토큰·개인정보·이벤트 원문·메모 본문을 노출하지 않는다. 2026-10-27 에이전트가 이 PC의 실제 브라우저에서 핵심 세 기능 시연과 오류 후 복구를 확인했다. 캡처는 저장소 밖에 보관한다. 제3자 재현·작업 관리자 동시 비교·실제 SDP/XDR 연결·공식 제출 수락은 여전히 미확인이다.

- 초기 인수인계의 작업 전 기준은 `e185263d9fcb480fbb6236d52ddfa3006159def0`, 제공 앱 버전은 `0.2.11`이었다. 초기 UI 모의 검사 15개 기록은 당시 결과이며 현재 새 기능 검사의 대체가 아니다.

- 이번 로컬 앱 개선에서 기존 5191 서버·수집기, 제공 5189 서버와 인증 계약은 변경하지 않았다. 기존 Git 기록, 미커밋 사용자 자료, 13~22단계 제출물, 운영 자격 설정을 보존한다. 실제 측정·모의 검사·운영 연결·제출 수락을 서로 다른 근거로 기록한다.
