# 워치독스 · 마지막 총공세 2~7일차 작업·인수인계 기록

> **UI:** 기록 타임라인형 · **포장 목표:** 공식 기본 포장 성공 후 사용자 단위 Inno Setup `setup.exe`. **작업 전 기준:** `e185263d9fcb480fbb6236d52ddfa3006159def0`. **원문 앱 버전:** `on-client/package.json` `0.2.11`. 이 문서 작성만으로 v1.0·운영 설치·공식 제출·실측 완료가 된 것은 아니다.

## 2일차 · CPU / 메모리 / 디스크

기존 제공 `on-client/public/app.js`와 학생 `extension.mjs`에는 일반 PC CPU·RAM·디스크를 측정하는 기능이 없었다. **중복 구현 대상이 없음을 먼저 확인했다.** 일반 권한의 Windows WMI/CIM 조회를 학생 `pc-monitor/collect.ps1`에 추가하고, 별도 5191 루프백 UI에서 CPU 사용률 %, 사용 메모리 GiB, 디스크 여유 GiB와 **항목별 측정 시각·출처·확인 불가 사유**를 표시한다. 사용자가 누른 실제 조회를 최대 5회 탭 메모리에 두고 직전 CPU %p 차이를 표시한다.

**검증 수준:** 코드 및 모의 입력으로 화면 표시/추이 동작 확인. 실제 사용자 PC의 수치·작업 관리자 비교는 **미확인**. 설명용 숫자를 측정 결과로 제시하지 않는다.

## 3일차 · 네트워크 / 방화벽 / 이벤트

`Get-NetAdapter -Physical`, `Get-NetFirewallProfile`, `Get-WinEvent`로 물리 링크·방화벽 Domain/Private/Public·최근 24시간 System/Application Level 2(오류)·3(경고)를 **읽기만** 한다. 로그별 1000건 상한 초과는 **부분 결과**로 기록한다. PC 기록 수치가 침해·공격 탐지라는 주장은 금지한다. 원본 5189의 `/api/diagnostics`와 별도 5191 `/api/sdp`로 확인 가능한 SDP 연결 모드를 구분하고, 기존 앱이 꺼져 있으면 확인 불가로 둔다.

**검증 수준:** 코드 확인, 외부 실제 Windows 이벤트 건수는 **미확인**. 운영 기기나 보안 설정에는 어떤 쓰기도 수행하지 않음.

## 4일차 · 화면·다시 조회·오류·키보드

`on-client/student/pc-monitor/index.html` · `app.js` · `style.css`에 PC용 반응형 카드·시간순 최근 조회·이벤트 종류 필터·수동 새로고침 버튼을 추가. 버튼만 조회를 실행하고 진행 중에는 비활성화/로딩, 실패 시 이전 PC/네트워크 결과를 삭제하고 **확인 불가 + 이유 + 다음 행동**을 보여 준다. native button/select/label, `textContent`, 키보드 포커스, 색상 외 상태 글을 함께 사용한다.

기존 보안 Agent `renderStatus` 학생 칸에 **별도 로컬 측정 화면 링크**를 추가했다. 5191은 별도 웹서비스이므로 **제공 보안 Agent의 5189번 화면 안에 직접 측정 기능이 통합된 것으로 주장하지 않는다**. 제공 `public/app.js`, `src/server.mjs`를 수정하지 않았다. `student/appearance.json`은 기존 원문에 없으므로 schema를 추측해 만들지 않았다. 학생 측정 페이지 자체 CSS는 설치형에 아직 들어가지 않았고 **포장 반영 미확인**이다.

**모의 확인:** 15개 UI 동작 시나리오에 대해 수동 요청, CPU/메모리 단위, 최근 5회 추이, 종류 필터, partial 표기, SDP 미연결, 요청 실패 때 낡은 수치 삭제를 확인. 실제 Windows 실행/화면은 미확인.

## 5일차 · 타인 실행 안내

`on-client/student/pc-monitor/INSTALL.md`에 Node v24.19.0, 새 PowerShell 세션 PATH, 원본 보존·기존 앱/동반 앱 실행·종료, 권한 오류·측정 한계·재현 순서를 정리했다. **실제 타인이 안내만 보고 실행해 성공했다거나 특정 오류가 발생했다는 증거는 아직 없다.** 따라서 독립 재현 검수는 미확인.

## 6일차 · 제공 포장 명령 및 설치 프로그램

**포장 준비 상태: 미완료.** 확인한 현재 Git 원문 `on-client/package.json`과 루트 `package.json` 양쪽에 **`package-app` 스크립트가 없다.** `APP_PACKAGE_MANIFEST.json` / 공식 `INSTALL.md` / 승인된 native host 런타임의 제공·설치 여부도 이 저장소에서 검증할 수 없다.

- 과제 요청에 따라 임의의 대체 `package-app` 스크립트나 승인 실행 호스트를 생성하지 않았다.
- `PROVIDED_RUNTIME_NOT_INSTALLED`, 앱 권한/운영키 대기 문구는 향후 공식 도구가 내는 경우 담당자에게 전달한다. 현재 **그 오류가 실행 결과로 출력됐다고 주장하지 않는다**.
- 공식 제공 도구·실행 호스트가 준비된 다음에만 포장 작업 커밋/실존하는 PNG 아이콘/비어 있는 출력 디렉터리를 검증하고 `npm run package-app -- --source . --out "<확인된 프로젝트 밖 경로>" --iconPath "<기존 PNG>" --finish-materials` 실행.
- 이 단계에서 `finish.commit.raw`, `finish.archive.tar.gz`, `app.zip`, `APP_PACKAGE_MANIFEST.json`, 공식 `INSTALL.md`, `setup.exe` 모두 **미생성**. 별도 학생 `pc-monitor/INSTALL.md`와 구분한다.
- 사용자 단위 Inno Setup은 **공식 실행 패키지와 승인된 호스트 실행 대상이 실제 존재한 뒤** 마법사로 제작한다. `PrivilegesRequired=lowest`와 사용자 디렉터리를 사용하고, 시작 메뉴 등록/제거 프로그램 동작을 확인한다. 실존하는 실행 대상이 없는데 가짜 바로가기를 만들지 않는다. SmartScreen/Defender 설정을 끄지 않는다.
- Inno Setup 공식 기준: `https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm`, `https://jrsoftware.org/ishelp/topic_consts.htm`.

## 7일차 · 시연 순서 및 제한

1. **보안 기록**: 기존 5189 → 보안 기록 → 사건 발생 시각 최신순과 종류별 필터. SDP 미연결이면 실제 XDR 기록 조회 성공을 주장하지 않는다.
2. **내 PC 측정**: 기존 학생 상태 화면의 링크 → 5191 → 다시 조회 → CPU·메모리·디스크의 실제 값/출처/시각 또는 확인 불가. **수치 시연은 아직 하지 않음.**
3. **주의·연결/이벤트**: 5191 네트워크·방화벽·System/Application 건수 → 종류별 필터 → 별도 SDP 모드. 이벤트 경고 수는 침해 판정 아님.

**최종 제출 상태:** 실 사용자 Windows 측정 스크린샷·공식 네 파일 묶음·앱 ZIP·설치 프로그램·시험0반 전용 다중 캡처 확인 화면의 실행 결과는 없음. 1~6장의 실제 앱 화면(비밀번호·키·개인정보 제외)을 준비할 수 있지만, 사진을 공식 패키지 칸에 잘못 넣지 않는다. **제출하지 않았고 결과·점수·운영 수용을 임의로 주장하지 않는다.**
