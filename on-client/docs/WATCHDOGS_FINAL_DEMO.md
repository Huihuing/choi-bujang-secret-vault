## 2. 실행

Windows PowerShell 5.1과 Node v24.19.0 세션에서 저장소 루트를 연 뒤 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\on-client\student\start-watchdogs.ps1
```

상세 환경 준비·중복 실행 방지·종료는 [프로젝트 폴더 실행 안내](../student/pc-monitor/INSTALL.md)를 따른다. 5189/5191이 이미 켜져 있으면 기존 화면을 사용한다. 새 런처에서 두 앱 모두 재사용 후 종료 코드 0, 기존 5189 재사용과 5191 신규 시작, 두 앱 모두 신규 시작을 실제 확인했다. Ctrl+C는 이번에 시작한 프로세스만 종료하고 재사용한 5189 HTTP 200을 보존했다. 검증 종료 시 두 앱은 실행 중이었다. PowerShell 5.1 파서 오류 0과 UTF-8 BOM도 확인했다.

정상 결과는 값·단위·출처·측정 시각이다. 실제 서비스 접속 실패 시 현재 수치를 지우고 이유·다음 행동을 표시했으며 재조회로 복구했다. 실제 로컬 HTTP 검사에서는 POST 405·다른 Origin 403·잘못된 Host 403을 확인했다.

## 4. 화면과 제출 자료 정리

대표 화면과 필요한 추가 화면은 실제 앱에서 확보한다. 측정값에는 단위·측정 시각·출처가 보이게 한다. 읽지 못한 값은 확인 불가로 유지하고, 계정·개인정보·키·토큰·확인 번호·메모 본문·이벤트 원문은 캡처하지 않는다.

6일차 자료는 [GitHub 저장소](https://github.com/Huihuing/choi-bujang-secret-vault)와 같은 작업의 40자리 SHA다. 저장소 루트에서 `git rev-parse HEAD`로 로컬 커밋을, `git ls-remote origin refs/heads/main`으로 원격 main을 확인하고 GitHub의 같은 커밋과 대조한다. 나중 작업의 커밋과 혼동하지 않도록 실제 제출할 때 이 두 값을 확인한다. 미커밋 변경은 그 SHA에 포함되지 않는다. 실제 제출·접수·수락을 확인한 경우에만 결과를 기록한다. 화면 캡처는 저장소 밖에 보관한다.

## 5. 시연 설명

워치독스는 학생용 PC 조회 기록과 Windows 측정값, 기존 보안 Agent의 연결 상태를 구분해서 보여 줍니다. 조회 기록은 직접 누른 요청의 성공·부분·실패·미연결 상태를 조회 완료순으로 보여 주며, 실제 XDR 사건과 출처가 다릅니다. 탭을 닫으면 PC 조회 이력은 사라집니다.

일반 사용자 권한으로 CPU·메모리·디스크를 읽고 단위·출처·측정 시각을 표시합니다. 실패한 값을 예제 숫자나 정상으로 바꾸지 않습니다. 네트워크·방화벽·Windows 이벤트는 읽기만 하며 경고·오류 건수는 공격 판정이 아닙니다. SDP가 미연결이면 운영 사건 수신이나 보안 조치 성공을 주장하지 않습니다.

## 6. 보존과 완료 표현

기존 Git 기록·사용자 자료·13~22단계 제출물·운영 자격 설정을 보존한다. 제공 인증·판정·서버 기능을 약화하거나 보안 설정을 끄지 않는다. 이번 과정의 실행·시연·저장소 제출 근거와 이전 포장 관련 이력을 구분한다.

현재는 **핵심 세 기능의 에이전트 로컬 시연·통합 실행·오류 후 복구를 확인한 상태**다. UI 모의 24개·서버 모의 9개와 실제 브라우저·HTTP 근거를 구분한다. 20건 상한·권한 부족·부분 표본은 모의 검사에 한정된다. 제3자 재현·작업 관리자 동시 비교·실제 SDP/XDR 연결·공식 제출 수락은 아직 미확인이다. 이번 로컬 개선에서 제공 서버·5191 서버와 수집기·인증 계약은 변경하지 않았다.
